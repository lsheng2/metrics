## Outcome And Current Boundary

Download a saved draft or finalized report as Markdown or Excel without another
source capture, model request, Save, publication or data-Git commit. A representative
rich-text/template/history/AR sample must retain its text, separate ticket rows,
links and date/status prefixes. HTML/JSON remain the full-format authority.

Current `ReportRenderer` produces HTML/plain text only. `PUBLICATION_FILES` and
`ReportPublicationReader` enforce exactly six immutable files. Therefore the new
formats are explicitly **derived exports**, not new files inside an old publication.
Published exports consume the verified original `report.html`; they never call
the current template renderer or reconstruct an old report from current source.
Existing HTML/plain downloads and all six original bytes stay unchanged.

The current HTML is a complete display projection of the saved report. Derived
formats do not become import/editing authorities. Full original audit JSON remains
in the existing publication. No export cache, alternate archive or SDK API is added.

## Libraries And Capability

Reuse existing `openpyxl==3.1.5`. Add `markdownify==1.2.3` and explicitly pin the
already installed `beautifulsoup4==4.15.0`. The downloaded Markdownify wheel was
inspected: MIT license, public `MarkdownConverter` subclass hooks, bs4/six runtime
dependencies. Use `html.parser` explicitly, not an environment-selected parser.
Dependencies load only when exporting; absence must not break manual editing or
original HTML/plain downloads. Only the selected reporting venv may be changed.

Markdown uses the mature converter with `escape_misc=True`, ATX headings and
autolinks disabled. Override only cell paragraph/break serialization so cumulative
`wwxx.x(Status):` updates remain separated by `<br>` in Markdown tables. Literal
HTML/Markdown punctuation in source text stays literal. Inline color/highlight
are intentionally not represented. Nested tables and spanning cells that cannot
be faithfully represented by this version fail explicitly, rather than silently
moving text to the wrong column.

Excel v1 exports text tables, not a rich-text restoration format. Preserve:

- Every source table's direct rows/cells in source order, including empty cells.
- In-cell paragraph/line breaks; an auxiliary full-text sheet retains non-table
  template content, notes, headings and ARs.
- One unambiguous safe hyperlink per cell. A Links sheet retains all link
  labels/destinations, including multiple links inside a cell.
- Formula-looking content as literal strings, including `=`, `+`, `-`, `@` and
  Excel error-looking values. No formula, macro, external workbook or data query.

Foreground/highlight and rich inline marks are deliberately omitted in Excel v1
and declared in its Information sheet and descriptor. The existing HTML/JSON keep
them unchanged. Nested user tables may be separate worksheets; outer cells also
retain their flattened text. Reject spanning cells rather than inventing a grid.
Use `openpyxl` for workbook logic and standard `zipfile` for stable member order/
timestamps; do not hand-write spreadsheet XML. Set static workbook properties via
the pinned writer API so wall-clock metadata does not change repeated exports.
Byte-repeatability is qualified in the pinned runtime, not claimed across arbitrary
future library/platform versions. Generator changes require a new revision.


Reuse `ReportAccessMixin`, actor/owner checks and private/no-store artifact headers.
Reject missing, unknown or duplicate query keys. No request body or caller HTML.
Success returns attachment bytes, `Content-Type`, safe filename,
`X-Report-Source-SHA256`, `X-Report-Export-SHA256` and
`X-Report-Export-Revision`. No error stack or private path is returned.
401/404 follow existing access behavior; 400 is invalid query, 413 is a resource
limit, 422 is unsupported source structure/content, 503 is unavailable dependencies.
POST is 405 and never performs conversion or mutation.
The existing HTML safety validator already rejects `rowspan`/`colspan` attributes;
such input remains `REPORT_ARTIFACT_INVALID` before format conversion. Do not weaken
that owner merely to reach the export adapter's narrower capability error.

## Bounds And Failure Atomicity

- Source HTML: at most 16MiB; result at most 32MiB.
- At most 64 tables, 100000 emitted cells and 100000 text lines. Markdown counts
  serialized output lines plus in-cell `<br>` breaks, including its metadata header.
- Excel cell text: at most 32767 UTF-16 units. XML-illegal control characters reject.
  Check before handing text to openpyxl, which must never silently truncate it.
- Unknown format, unsafe HTML/link, wrong input hash, nested/spanning Markdown
  table, spanning Excel cell and exceeded bounds fail before returning an artifact.
- In-memory conversion only. Failure writes no partial export or publication.
- Dependency/import/version errors map to `REPORT_EXPORT_UNAVAILABLE`; no fallback
  claiming an unqualified format. Original HTML/plain and manual editing still work.

New report errors: `REPORT_EXPORT_UNAVAILABLE`, `REPORT_EXPORT_UNSUPPORTED`.
Use existing `REPORT_LIMIT`, `REPORT_INVALID`, `REPORT_ARTIFACT_INVALID` where exact.
New views own translated export messages; do not enlarge the 399-line report view.
